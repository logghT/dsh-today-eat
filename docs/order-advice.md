# 点单建议：连锁品牌靠谱推荐，小店不硬编

> 用户需求：点单建议靠谱一点——网上能查到信息的连锁店按真实信息公开菜单推荐；查不到信息的家常馆子让顾客自行点餐。

## 行为

每家附近的店都会带一条 `suggestion`：

- **命中连锁品牌**（约 35 个常见品牌）：
  - 文案以「【连锁品牌·公开菜单】」开头；
  - 给出该品牌公开菜单里的常见单品（如肯德基：吮指原味鸡、香辣鸡腿堡、老北京鸡肉卷、蔬菜沙拉）；
  - 按当前阶段给更具体的选法：健身/健康期给更轻的搭配（如原味鸡去皮 + 蔬菜沙拉 + 无糖茶），放松/放纵期按招牌点；
  - 统一附「菜单可能调整，以门店为准」。
- **查不到可靠公开菜单的店**：
  - 文案以「【查不到公开菜单】」开头；
  - 建议到店看菜单、问老板招牌菜，按自己的口味和预算点；
  - 不出现任何具体菜名，不根据店名猜菜系/招牌。
- 所有店的点单建议都独立展示；全局只保留一句「连锁按公开菜单，小店自行点单」的说明。

## 识别规则

`src/core/chain-menu.js`：

- `matchChainBrand(name)`：店名去空格/标点、转小写后做「别名包含匹配」，长别名优先（例如「太二酸菜鱼(万达店)」→ 太二酸菜鱼；「KFC 某门店」→ 肯德基）；
- `buildOrderSuggestion(name, phaseKind)`：返回 `{ kind: 'chain' | 'unknown', brand, items, fit, text }`；
- 只有命中品牌才给具体单品；未命中一律走「未知」文案。

## 数据来源与边界

- 本地维护的**公开常见菜单单品**，不运行时联网抓取、不逆向外卖平台；
- 品牌菜单会随季节/门店调整，文案始终带「以门店为准」；
- 知识库未覆盖的品牌（包括部分地方连锁）按「查不到公开菜单」处理，不会硬编；
- 这是「可信的有限推荐」，不是实时菜单/库存/价格查询。

## 链路

- `lib/amap.js#searchNearby`：为每个 POI 附 `suggestion`（文案）与 `orderKind`（chain/unknown）；全局 `suggestions` 只留一句说明。
- `lib/api.js#handleNearby`：原样透传 items（每项含建议）。
- `lib/tool.js`：`NEARBY_ITEM_SCHEMA` 增加 `suggestion`；`projectNearbyItems` 透传；render 在每家店下面输出「点单：…」。
- `src/client/tabs/today.jsx`：每家店展示 `点单建议：…`，连锁用品牌色、未知用弱化色（`.tde-place-suggestion.is-chain/.is-unknown`）。
